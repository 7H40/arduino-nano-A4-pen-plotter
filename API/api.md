## 1. output

На выходе ты должен отправлять на Нано только текстовые команды через Serial (USB) со скоростью 115200 baud, каждая команда заканчивается `\n`.

Нано будет на каждую команду от матери отвечать `ok\n` (или ошибкой или пашел нахуй), чтобы твой скрипт ЖДАЛ перед тем как отправить следующую, именно ждал с заваленным ебальником

---

## 2. Framing и парсер

- Одна команда = ровно одна строка, `\n`. Максимум **64 байта** (у нано RX-буфер 64 байта - если питон шлёт не дождавшись `ok`, буфер переполняется и взрывается хатя у тя).

- Парсер: регистр только верхний (`G0`, не `g0`). Пробелы между токенами. Лишние токены - игнор

- `X1.5` - Всегда ошибка

- Парсить через `strtol`, проверять `errno` и диапазон. Что не влезло в `int32_t` или вне `travel` - ошибка, терпеть

- Межбайтовый таймаут на нано: если строка не закрылась `\n` за 200 мс — сбросить буфер, никто не будет это ранить. Иначе порванный туз по питанию превратится в валидную команду.
- На пустую строку всегда будет ответ 'ok'

## 3. DTR-ресет и boot banner

Нано при старте шлёт только одну строку и ты должен ее принять:

```

PLOTTER <ver> steps_per_mm=<N> travel=<X>,<Y>

```

Пример: `PLOTTER 1.0 steps_per_mm=80 travel=24000,16000`

Питон парсит, сверяет `steps_per_mm` со своей константой (80). Не совпало - пашел нахуй. Хост ждёт баннер до 5 секунд если не получил то сидит терпит.

---

## 4. Координаты

- Все координаты (`X`, `Y`) - это ТОЛЬКО **ЦЕЛЫЕ ЧИСЛА (int32_t)** в двигательных шажках
- Питон переводит миллиметры в шаги (типа, 1 мм == 80 шагов) и отправляет уже готовые шаги.
- дробное нельзя вообще

## 5. Диалект

1. `G0 X<int> Y<int>\n`
   Быстрое перемещение (Rapid move) с поднятой головкой
   `G0 X1500 Y0`

2. `G1 X<int> Y<int>\n`
   Линейное перемещение с опущенной головкой. Рисует линию от текущей позиции до `X,Y`
   `G1 X1800 Y200`

3. `M3\n`
   Опустить перо Включает соленоид твой

4. `M5\n`
   Поднять перо Выключает соленоид

5. `G28\n`
   Homing. Найти концевики (limit switches) по осям X и Y устанавливает 0ые корды

6. `G92 X<int> Y<int>\n`
   Установить текущие физические координаты как заданные (без движения моторов).
   `G92 X0 Y0` (обнулить текущую позицию).

`ok` уходит только после полного завершения действия.** То есть прислал `G1 X100 Y100` - нано доехал, потом отправил `ok`. Прислал `M3` - соленоид щёлкнул, перо село и потом ток `ok`

## 6. Ошибки

- `ok\n` - всё ок
- `error:<код> <текст>\n` - ошибка 
- `<данные>\n` - только для квери-команд (`M114`)

Коды ошибок:

- 0x4  команда неизвестна 
- 0x5  параметр битый (float, мусор, лишний токен) 
- 0x1  за пределами рабочего поля (soft limit) 
- 0x3  концевик сработал во время движения 
- 0x2 homing не доехал / таймаут 
- 0x6 команда запрещена в текущем состоянии ( типа `G0` до `G28`) 

Хост читает ОДНУ строку и решает

## 7. Throughput

Синхронный `ok` после движения = один round-trip на сегмент. На 115200 это ~1–2 мс минимум, плюс время самого хода. Кривую будем аппроксимировать тысячами коротких `G1` — это секунды накладных расходов.

Для курсового ок. Но **впиши в контракт**: «v1 строго синхронный; при необходимости v2 — `ok` на приём в кольцевой буфер + `M400` (wait for motion)». Это снимает будущий спор «почему так медленно».
