# Версия 2.9.4

---

## 1. Serial

- Baudrate: **115200**, 8N1, без flow control.
- Порт открывается по USB. Нано ресетится по DTR при открытии порта - это нормально и ожидаемо, а не баг.
- Хост после открытия порта: ждёт **2000 мс**, чистит буфер, читает баннер (раздел 2).
- МК не ждёт хоста. Шаги генерятся в таймере, запись в порт идёт через 64-байтное TX-кольцо: строка до 96 Б досылается кусками и может придержать main loop максимум на ~8 мс - движению это не мешает. Если хост не читает, события копятся в очереди (4 слота), дальше не лезут: растёт счётчик `lost`. `0x3A EVDROP` имеет **зарезервированный слот** и уходит в обход очереди, как только TX освободится, с накопленным `lost=`.

## 2. Boot Banner

МК отправляет **ровно одну строку** после инициализации.

```
PLOTTER <ver> proto=<N> spm=<X>,<Y> travel=<X>,<Y> home=<0|1> reset=<R> crash=<N>
```

Пример:
```
PLOTTER 2.0.F proto=2 spm=80,80 travel=24000,16000 home=0 reset=POR crash=0
```

| Поле     | Нахуя                                                                                                                                                                                                   |
| ---      | ---                                                                                                                                                                                                     |
| `ver`    | версия прошивки, для человека. Не длиннее 8 символов                                                                                                                                                    |
| `proto`  | версия протокола. **Не совпал - хост не начинает работу** (связь при этом не рвёт)                                                                                                                      |
| `spm`    | шагов на мм, по осям X,Y. Это **номинал из EEPROM**: DIP-переключатели TB6600 прошивка не читает, так что `spm` не истина, а заявка. Хост сверяет со своим профилем и предупреждает; рвать связь нельзя |
| `travel` | рабочее поле в шагах, по осям X,Y. Допустимый диапазон координат всегда `0..travel`. Ограничения конфига: `travel` ≤ 999999, `spm` ≤ 999, `ver` ≤ 8 символов - тогда баннер гарантированно ≤ 96 Б       |
| `home`   | `0` - координатам верить нельзя, нужен `G28`                                                                                                                                                            |
| `reset`  | причина последнего **старта МК**: `POR` (питание), `EXT` (reset-пин), `BOR` (просадка), `WDT` (собака), `UNK`. `0x18` стартом не считается и это поле не меняет                                         |
| `crash`  | счётчик плохих стартов, uint16 с насыщением на 65535: инкремент на `WDT`/`BOR`, лежит в EEPROM. Вырос между коннектами - ищи железо, а не софт                                                          |

**Что делает хост с баннером:**

1. `proto` не совпал -> работа не начинается, но **связь не рвётся**: `?`, `M114`, `M115`, `$$` остаются доступны для диагностики. Иначе не прочитаешь баннер и не поймёшь, что стряслось.
2. `spm`/`travel` берутся **с МК**: это то, что прошивка считает правдой о своём железе. Хост сверяет со своим профилем и, если не сошлось, **предупреждает в лог/на экран и продолжает работу**. Рвать связь нельзя - `spm` зависит от DIP-переключателей TB6600, которые прошивка прочитать не может.
3. `home=0` -> первым делом `G28`, иначе половина команд отвалится по `error:0xFB NO_HOME`.
4. Баннер отправляется автоматически один раз после инициализации. Получить его снова - только через `0x18` или `M115`.
5. `M115` печатает баннер заново с **актуальными** `home`, `travel`, `spm`, `crash`. `reset` - причина последнего старта МК, она не меняется ни от `M115`, ни от `0x18`.
6. Сразу после баннера хост **обязан** отправить `?` и проверить `S`: баннер не несёт состояние, а невалидный конфиг (`0x66`/`0x67`) уводит МК в `SALA` ещё до баннера. Без этого шага хост получит `error:0xF5` на всё и не поймёт, почему.

## 3. Framing

- Кодировка ASCII `0x20..0x7E`.
- `\r` (0x0D) - разделитель токенов наравне с пробелом: `\r\n` в конце работает как `\n`, а `1\r2` это два токена, то есть `error:0xF2 UNKNOWN_CMD`, а не `12`.
- Байты `0x00-0x1F` (кроме `\n`, `\r`, `\t` и `0x18`), `0x7F` и `0x80-0xFF` отбрасываются. На пачку таких байт уходит событие `!EVENT <seq> 0x37 EVRXNOI n=<сколько>`, не чаще одного раза в 100 мс.
- Конец строки: строго `\n` (0x0A).
- **Строка хост -> МК: максимум 64 байта включая `\n`** (у Нано RX-буфер 64 Б). Realtime-байты (`!`, `0x18`) в этот лимит не входят: они вырезаются до подсчёта, иначе лимит обходился бы вставкой `!`. Переполнение -> строка выбрасывается целиком, ответ `error:0xF6 LINE_TOO_LONG`.
- **Строка МК -> хост: максимум 96 байт.** Шлётся через 64-байтное TX-кольцо кусками (см. раздел 1), так что лимит - это договорённость, а не размер буфера.
- Регистр **не важен**: парсер приводит к верхнему. `g1` = `G1`.
- Пробелы и табы между токенами - любые, сколько угодно. Ведущие/хвостовые - игнор.
- Одна строка = ровно одна команда. Две команды в строке -> `error:0xF2 UNKNOWN_CMD`.
- Числа: только десятичные целые. `+`/`-` разрешены, `0x`/дробь/экспонента - `error:0xF1 BAD_PARAM`. Парсинг через `strtol`, проверка `errno` и диапазона `int32_t`.
- Строка без токенов (только пробелы, табы или `\r`) эквивалентна пустой -> `ok` и считается такой же командой, как любая другая: терминальный ответ ровно один. Это же keepalive, продлевает `LACT`.
- Межбайтовый таймаут: **200 мс**. Не закрылась строка - буфер сбрасывается, ответ `error:0xF7 LINE_TIMEOUT`.
- **Ресинхронизация.** После `0xF6` и после `0xF7` всё, что приходит до ближайшего `\n`, игнорируется, сам `\n` съедается, ответ ровно один. Хвост битой строки не парсится как новая команда - иначе поедет счётчик «отправил/получил».
- Комментариев нет. `;` и `(` - `error:0xF2`.
- **Байтовый realtime.** `!` (0x21) и `0x18` распознаются на уровне приёма байта, вне линии: `\n` не нужен, в буфер строки не попадают, `LINE_TIMEOUT` не порождают, межбайтовый таймер не сбрасывают и в лимит 64 Б не входят. Внутри строки `!` вырезается и срабатывает, строка продолжается; `0x18` сбрасывает всё. Ответы: `!` порождает `ok` (и `error:0xF9` прерванной команде, если она была), `0x18` на сам байт не отвечает вообще, но прерванной команде шлёт `error:0xF9` и затем баннер. `\n` после `!` слать не надо - получишь пустую строку и лишний `ok`, это вина хоста.

## 4. Sync & Timing

### Классы команд

| Класс             | Что                          | Ответ                                                                                                           |
| ---               | ---                          | ---                                                                                                             |
| `EXEC`            | `G0 G1 G28 G4 M3 M5 M17 M18` | `ok` **после** завершения                                                                                       |
| `SET`             | `F M201 G92 M999`            | `ok` сразу после применения                                                                                     |
| `QUERY`           | `M114 $$ M115`               | строки данных, **затем** `ok`                                                                                   |
| `ASYNC`           | `?`                          | ровно одна `<STATE ...>`, **без `ok`**                                                                          |
| `REALTIME-строка` | `M112`                       | `ok` в течение одного цикла main loop после `\n`; прерванной команде - `error:0xF9 ABORTED` **перед** этим `ok` |
| `REALTIME-байт`   | `!`                          | `ok`; прерванной команде - `error:0xF9` перед этим `ok`                                                         |
| `RESET-байт`      | `0x18`                       | **ноль ответов**, новый баннер                                                                                  |

### Сколько ответов ждать

| Отправлено                  | Терминальных | Что придёт                                                                   |
| ---                         | ---          | ---                                                                          |
| `EXEC` `SET` `QUERY` `M999` | 1            | `ok` или `error:`                                                            |
| `?`                         | 0            | одна `<STATE ...>`                                                           |
| `M112`                      | 1 + 1 + push | `ok`; если что-то выполнялось - ещё `error:0xF9` той команде и `<STATE ...>` |
| `!`                         | 1 + 1 + push | то же                                                                        |
| `0x18`                      | 0            | баннер, ждать до 5000 мс                                                     |

**Инвариант.** На каждую принятую команду - ровно один терминальный ответ (`ok` или `error:`). Если команда в этом состоянии запрещена, её терминальный ответ и есть `error:0xF5 STATE` (в `SBUS` - `0xF4 BUSY`), и это считается, как обычный ответ. Исключения ровно два, и они не терминальные: `?` отвечает одной `<STATE ...>`, принятый `0x18` не отвечает вообще и печатает баннер. Хост считает «команды, обязанные ответить» отдельно от этих двух, и счётчик сходится.

`+ push` в таблице значит «плюс `<STATE ...>`, если `S` или `M` реально изменились»: `!` в `SIDL`/`SEST` ничего не меняет и пуша не даёт.

Правило разбора ответов

1. Хост читает строки до первого `ok` или `error:` - это терминальный ответ на текущую команду. Всё, что пришло раньше и не начинается с `<` или `!`, - данные этой команды.
2. Строки, начинающиеся с `<` или `!`, - асинхронные. К текущей команде не относятся, разбираются отдельно.
3. Строки данных (ответы `M114`, `$$`) никогда не начинаются с `<`, `!`, `ok`, `error`.
4. `0x3A EVDROP` значит, что события потеряны. Сделай `?` и сверь `x`/`y`/`home`, иначе живёшь со stale state.

### Realtime во время движения

МК парсит RX **и во время движения** (шаги генерятся в таймере, парсер крутится в main loop). Пока команда `EXEC` выполняется, принимаются только `?`, `M112`, `!`, `0x18`. Любая другая -> `error:0xF4 BUSY`.

Именно поэтому `M112` доставляется: хост имеет право писать в порт, не дожидаясь `ok`. **Хост обязан** уметь это (отдельный поток чтения или отмена ожидания) - иначе аварийный стоп не работает в принципе.

`M114` во время движения **запрещён**: это `QUERY`, его `ok` прилетит раньше `ok` от `G1`, и хост закроет не ту команду. Позицию во время хода бери из `?` - там `x`/`y` живые.

**Порядок при аварии.** Единый для всех аварийных сценариев: `!EVENT` -> терминальный ответ текущей команде -> `<STATE ...>` (если `S` изменилось) -> `ok`, если он ещё кому-то положен. Так, `M112` во время `G1`: `EVESTOP` -> `error:0xF9` (это `G1`) -> `<STATE S=0xC8>` -> `ok` (это `M112`). `EVLIMNH` во время `G1`: `0x60 EVLIMNH` -> `error:0xFA` (это `G1`) -> `<STATE S=0xC7>`; отдельного `ok` нет, `error` и был терминальным. `EVHOMFL` во время `G28`: `0x63 EVHOMFL` -> `error:0xF8` (это `G28`) -> `<STATE S=0xC7>`.

### Таймауты

| Параметр                   | Значение                                                                                                                                                 | Кто следит                                |
| ---                        | ---                                                                                                                                                      | ---                                       |
| Пауза после открытия порта | 2000 мс                                                                                                                                                  | хост                                      |
| Баннер не пришёл за        | 5000 мс                                                                                                                                                  | хост -> нано не ресетнулся/прошивка мертва |
| Межбайтовый таймаут строки | 200 мс                                                                                                                                                   | МК                                        |
| Простой линка -> `LLOS`     | 9000 мс без единого байта **и** ничего не выполняется                                                                                                    | МК                                        |
| Watchdog                   | 2000 мс, сбрасывается в main loop **независимо от трафика**                                                                                              | МК                                        |
| Ожидание `ok`              | `max(2000, 1000 + 3000·d/F + G4)` мс                                                                                                                     | хост                                      |
| Таймаут `ok` для `G28`     | Обе оси (`G28`) - 65000 мс, одна ось (`G28 X`) - 35000 мс. Формула `d/F` не применяется: путь до концевика неизвестен, едет на `$home_fast`/`$home_slow` | хост                                      |
| Таймаут `ok` -> что делать  | только `?`, сверить `x`/`y`/`home`; расходится - `M112` или `0x18`                                                                                       | хост                                      |

`d` - путь в шагах, `F` - подача в шаг/с. Коэффициент 3 - запас на трапецию разгона, люфт и `$pen_dn`. **Формула `d/F` без запаса неверна**: реальное время всегда больше (разгон, тормоз, dwell, оверхед на `ok`), и хост, посчитав впритык, оборвёт валидное движение.

**Никогда не переотправлять `EXEC`.** `G1`/`G0`/`G28` не идемпотентны: повтор = повторное движение по бумаге. Таймаут не значит «не дошло», чаще значит «дошло, но `ok` не успел». После таймаута - только `?`, сверить позицию и `home`, и уже по факту решать.

**Таймаут линка не действует, пока МК что-то выполняет.** Иначе линия на 20 секунд = «хост пропал» = остановка посреди линии.

### Бюджет

RX 64 Б + TX-кольцо 64 Б + очередь событий 4 + планировщик + стек ≈ 1.3 КБ из 2 КБ. OLED 128×32 с полным фреймбуфером - это 512 Б, четверть всей RAM, в бюджет не влезает: экран только в page-режиме, по 8 строк, без полного кадра. Не влезает и так - режем экран, протокол не трогаем.

## 5. States & Events [S&E]

### 5.1 Главное правило

**Состояние** - устойчивое, машина всегда в ровно одном. **Событие** - факт, доставляется один раз, с порядковым номером.

Домены ортогональны: система может быть `SREA` + `LACT` + `MCRU` + `TDWN` одновременно.

Состояний - четыре домена (`SYS`, `LINK`, `MOT`, `TOOL`). Событий - куча, они несут severity.

### 5.2 Как это летит по проводу

```
# снимок состояния: ответ на `?` и пуш по правилам ниже
<STATE S=0xC1 L=0xCE M=0xD0 T=0xE0 x=1200 y=400 home=1>

# событие: seq - uint16, оборачивается 65535->0; code - hex, полоса = severity
!EVENT <seq> 0x<код> <ALIAS> [<k>=<v> ...]
!EVENT 17 0x0B EVTLDN
!EVENT 18 0x30 EVLMBND axis=X
```

**Когда шлётся пуш.** При смене `L` или `T`, при смене `S` (кроме входа в `SBUS` и кроме `0x18` - там вместо пуша идёт баннер) и по завершении `EXEC`-команды, если итоговое состояние отличается от того, что было до неё. Завершение с ошибкой тоже даёт пуш, но только через смену `S` (`SALA`/`SEST`), а не отдельно. `SET` и `QUERY` пуш не шлют, если не меняют `S`/`L`/`T` - поэтому после `M114` в разделе 11 пуша нет. Транзитные состояния (`SBUS`, `MHOM`, `MSTP`, `MACC`, `MCRU`, `MDEC`, `MDWE`, `MSEE`, `MSLW`, `MBKL`, `TMOV`, `TSET`) в пуш **не** попадают, иначе это флуд; их видно только через `?`.

`seq` стартует с 1 после любого старта МК и сбрасывается при `0x18`: первый event после `0x18` снова имеет `seq=1`. Дыра в `seq` = потерянные события; абсолютное значение не значит ничего, важна только непрерывность.
`<STATE ...>` в ответ на `?` не является терминальным ответом и не закрывает ожидание `ok` у текущей команды - его можно поллить в любой момент, включая `SBUS`.


### 5.3 Карта диапазонов

Шкала одна на весь протокол: состояние, событие и ошибка получают код из общих `0x00-0xFF`. Внутри полосы коды идут подряд - следующий свободный всегда `последний + 1`, дырок нет.

| Диапазон    | Что           | Занято        |
| ---         | ---           | ---           |
| `0x00-0x2F` | события INFO  | `0x00`-`0x13` |
| `0x30-0x5F` | события WARN  | `0x30`-`0x3C` |
| `0x60-0x8F` | события ALARM | `0x60`-`0x69` |
| `0x90-0xBF` | события FATAL | `0x90`-`0x95` |
| `0xC0-0xEF` | состояния     | `0xC0`-`0xE4` |
| `0xF0-0xFF` | ошибки        | `0xF0`-`0xFF` |

### 5.4 Состояния

#### System `S=`

| Код    | Алиас | Имя             | Что это                                                                                             |
| ---    | ---   | ---             | ---                                                                                                 |
| `0xC0` | SBOO  | SYSBOOT         | инициализация, баннера ещё нет. Хост видит только «тишину»                                          |
| `0xC1` | SREA  | SYSREADY        | готов, моторы под током, можно работать                                                             |
| `0xC2` | SIDL  | SYSIDLE         | простой, моторы обесточены (`M18`). Любая `EXEC` с движением сама подаёт ток и уводит в `SREA`      |
| `0xC3` | SBUS  | SYSBUSY         | выполняю команду `EXEC`                                                                             |
| `0xC4` | SPAU  | SYSPAUSE        | пауза (`!` или кнопка), движение прервано, координаты целы                                          |
| `0xC5` | SSLP  | SYSSLEEP        | глубокий сон, выйти только физической кнопкой                                                       |
| `0xC6` | SMNT  | SYSMNTNC        | сервисный режим: G-code не принимается, только `?`/`M112`/`M999`/`$$`/`M115`                        |
| `0xC7` | SALA  | SYSALARM        | софт-лок. Выход `M999`                                                                              |
| `0xC8` | SEST  | SYSESTOP        | аварийный стоп: моторы обесточены. Выход - `M999`, а если вход был по кнопке - сначала отпустить её |
| `0xC9` | SFAU  | SYSFAULT        | аппаратная блокировка: железо сказало «стоп» само. Только снять питание                             |
| `0xCA` | SFLT  | SYSFAULTLATCHED | защёлкнутая: попытка выйти (`M999`) не удалась. Только снять питание                                |
| `0xCB` | SPWR  | SYSPOWER        | brownout, полный shutdown                                                                           |
| `0xCC` | STHR  | SYSTHERMAL      | перегрев //UNUSED (термисторов нет)                                                                 |
| `0xCD` | SPAN  | SYSPANIC        | //UNUSED, последний рубеж                                                                           |

Входы в состояния, которые протоколом не включаются:

- `SMNT` и `SSLP` включаются только кнопкой/меню. Команды внутри принимаются (`?`, `M112`, `M999`, `$$`, `M115` для `SMNT`; `?`, `M112` для `SSLP`), но выйти из них командой нельзя - только физической кнопкой.
- `TMOV`, `TSET` - не мёртвые: `M3`/`M5` проходят их всегда (`TMOV` - пока едет соленоид, `TSET` - пока выжидается `$pen_dn`/`$pen_up`). Наружу видны только через `?`. Перо чисто таймерное, датчика касания нет.
- `MPRK` - команды нет, состояние недостижимо.

### 5.5 События

Код события - **hex**, полоса задаёт severity: `0x00-0x2F` INFO, `0x30-0x5F` WARN, `0x60-0x8F` ALARM, `0x90-0xBF` FATAL. Чем старше полоса - тем больше пиздеца произошло.

Алиас - справочный, произвольной длины (4-8 символов): парсить по токену, а не по фиксированной ширине, свитчить по коду.

### 5.6 Что сбрасывает `home` в 0

`home=1` ставится **только** успешным `G28`. В `0` сбрасывают:

- любой старт МК (`POR`/`EXT`/`BOR`/`WDT`) - баннер `home=0`;
- `0x18` - сброс состояния, моторы при этом не двигались, но координаты всё равно объявляются недостоверными;
- `0x60 EVLIMNH` (упёрся не в хоуминге);
- `0x90 EVESTOP`, `M112`, `0x93 EVHWFLT` - после них позиция физически неизвестна;
- `M999` (выход из `SALA`/`SEST`) - всегда, даже если авария позицию не теряла;
- `M18` (моторы обесточены - свободный проворот не исключён).

`G92` **не** сбрасывает: моторы не двигались, меняется только система координат.

### 5.7 Переходы

Таблица - это переходы, а не конечный результат команды: `EXEC` из любого состояния сначала уводит в `SBUS` и только по завершении возвращает в `SREA`.


| Из                                | По чему                                       | В                                                                             |
| ---                               | ---                                           | ---                                                                           |
| `SBOO`                            | инициализация ок                              | `SREA` (`home=0`)                                                             |
| `SREA` / `SIDL` / `SPAU`          | `EXEC` (`G0` `G1` `G28` `G4` `M3` `M5` `M17`) | `SBUS`                                                                        |
| `SBUS`                            | завершено                                     | `SREA`                                                                        |
| `SBUS`                            | завершено (`M18`)                             | `SIDL`                                                                        |
| `SREA` / `SIDL` / `SPAU`          | `M18`                                         | `SBUS`, по завершении `SIDL`                                                  |
| `SPAU`                            | `SET` / `QUERY`                               | остаётся `SPAU`                                                               |
| `SBUS`                            | `!`                                           | `SPAU`, `M=MOTHOLD`                                                           |
| `SREA`                            | `!`                                           | `SPAU`, `M=MOTHOLD`                                                           |
| `SALA`                            | `!`                                           | `ok`, остаётся `SALA` (софт-лок паузой не снимается), `M=MOTHOLD`             |
| `SIDL` / `SEST`                   | `!`                                           | `ok`, состояние не меняется - моторы обесточены                               |

| `SALA` / `SEST`                   | `M999`                                        | `SREA` (`home=0`)                                                             |
| `SEST`                            | `M999`, кнопка ещё нажата                     | `error:0xF5 STATE`, остаётся `SEST`                                           |
| любое, кроме `SFAU` `SFLT` `SPWR` | `0x18`                                        | `SREA` (`home=0`), новый баннер, `seq` с 1                                    |
| любое                             | `EVLIMNH` / `EVCFGER` / `EVEESUM`             | `SALA`                                                                        |
| любое                             | `EVESTOP`                                     | `SEST`                                                                        |
| любое                             | `EVPWRLS`                                     | `SPWR`                                                                        |
| любое                             | `EVHWFLT` / `EVTHRMC`                         | `SFAU`                                                                        |
| `SFAU` / `SFLT` / `SPWR`          | всё, кроме `?` и `M112`                       | `error:0xF5 STATE`, выхода нет                                                |
| `SFAU` / `SFLT` / `SPWR`          | -                                             | только снять питание                                                          |
| любое                             | кнопка/меню                                   | `SMNT` или `SSLP` (пуш `<STATE>` уходит)                                      |
| `LACT`                            | 9 с тишины без работы                         | `LLOS`                                                                        |
| `LLOS`                            | любой байт                                    | `LACT`                                                                        |
| `MHOM` (при `S=SBUS`)             | `G28` без аргументов завершён                 | `M`: `MIDL`, `S`: `SREA`, `home=1`                                            |

- `!` переводит мотосостояние в `MOTHOLD` (`0xDA`) только если моторы под током (`SREA`/`SBUS`/`SPAU`/`SALA`). В `SIDL`/`SEST` они обесточены, там `!` - просто `ok`: держать нечем.
- Команды «продолжить» нет. Хост пере-отправляет `G1` с той же целью, перо осталось опущенным, линия продолжается с точки останова.
- `SFLT` отличается от `SFAU` только причиной: `SFLT` - защёлкнулось после неудачного `M999`, `SFAU` - железо отказало сразу.

## 6. Core Commands

Все координаты - абсолютные шаги, `0..travel`. Перо `G0`/`G1` **не трогают** - только `M3`/`M5`.

| Команда                     | Класс    | Что                                                                                                                                                                                                                                                                                                                                         |
| ---                         | ---      | ---                                                                                                                                                                                                                                                                                                                                         |
| `G0 X<int> Y<int>`          | EXEC     | быстрый ход на подаче `$frapid`, `F` игнорируется. `X` и `Y` обязательны: без любого из них - `error:0xF1 BAD_PARAM`                                                                                                                                                                                                                        |
| `G1 X<int> Y<int> [F<int>]` | EXEC     | рабочий ход, подача модальная или своя. `X` и `Y` обязательны, отсутствие любого - `error:0xF1 BAD_PARAM`                                                                                                                                                                                                                                   |
| `G4 P<int>`                 | EXEC     | пауза, 0..600000 мс. **Неблокирующая**: время выжидает main loop, `wdt_reset()` продолжает тикать. `P0` допустим: `ok` сразу и `0x09 EVDWEND ms=0`                                                                                                                                                                                          |
| `G28 [X] [Y]`               | EXEC     | хоуминг. Без аргументов - обе оси по очереди, сначала X потом Y; **только это** ставит `home=1`. Один аргумент - одна ось и **всегда `home=0`** (нестандартно: флаг один на всю машину, поэтому частичный хоуминг его сбрасывает). `G28 X Y` запрещён -> `error:0xF2 UNKNOWN_CMD`. На ось 30 с; `$lim=0` по оси -> `error:0xF8 HOMING_FAILED` |
| `G92 X<int> Y<int>`         | SET      | объявить текущую позицию такой, без движения. Оба аргумента обязательны. Диапазон проверяется: вне `0..travel` -> `error:0xF3 SOFT_LIMIT`                                                                                                                                                                                                    |
| `M3 [S<0..255>]`            | EXEC     | опустить перо. `S` переопределяет ШИМ удержания **только на эту команду**; без `S` берётся `$pen_pwm`. `S` вне `0..255` -> `error:0xFE RANGE`                                                                                                                                                                                                |
| `M5`                        | EXEC     | поднять перо                                                                                                                                                                                                                                                                                                                                |
| `M17`                       | EXEC     | подать ток на моторы                                                                                                                                                                                                                                                                                                                        |
| `M18`                       | EXEC     | снять ток, `home=0`                                                                                                                                                                                                                                                                                                                         |
| `M114`                      | QUERY    | позиция: `X<int> Y<int> F<int> PEN=0/1 HOME=0/1` + `ok`. В `SBUS` запрещён (`error:0xF4`) - во время хода бери `?`                                                                                                                                                                                                                          |
| `M112`                      | REALTIME | аварийный стоп. Мгновенно, `home=0`, `SEST`. Ответ `ok`; прерванной команде - `error:0xF9 ABORTED` **до** этого `ok`. В `SFAU`/`SFLT`/`SPWR` принимается, но состояние не меняет                                                                                                                                                            |
| `M999`                      | SET      | выход из `SALA`/`SEST` -> `SREA`, `home=0`. Обычная строка с `\n`, не байт. Ответ `ok`; если вход в `SEST` был по кнопке и она ещё нажата - `error:0xF5 STATE`, состояние не меняется                                                                                                                                                        |
| `M115`                      | QUERY    | повторить баннер + `ok`                                                                                                                                                                                                                                                                                                                     |

Замечания по модальности:

- Любая `EXEC` из `SIDL` (кроме `M18`) сама подаёт ток на моторы - неявный `M17`. Отдельная `M17` перед движением не нужна, по завершении состояние возвращается в `SREA`. `SIDL` значит «простаиваю без тока», а не «ток отключён принудительно».

- `G0` **не меняет** модальный `F`: он всегда едет на `$frapid`.
- `G1` без `F` едет на модальном `F`; `G1 ... F1200` меняет модальный `F` на 1200 (стандартное поведение G-code).
- `M201` требует оба аргумента; `M201 X100` без `Y` -> `error:0xF1 BAD_PARAM`.

## 8. Settings

`$$` печатает строки `$<ключ>=<значение>`, затем `ok`. Значения - **read-only**: запись в EEPROM отдельный риск по износу и валидации, в протоколе её нет.

```
$spm=80,80
$travel=24000,16000
$f=800
$fdef=800
$fmax=4000
$frapid=2500
$accel=1000,1000
$home_fast=800
$home_slow=150
$bl=0,0
$pen_dn=40
$pen_up=20
$pen_pwm=255
$lim=1,1
$dir=1,1
ok
```

`$spm`/`$travel` дублируются в баннере - это нормально, баннер читается до `$$`. Из EEPROM берутся `$spm`, `$travel`, `$bl`, `$pen_*`, `$lim`, `$dir`, `$fdef`, `$fmax`, `$frapid`, `$home_*` и стартовое `$accel`; меняются в рантайме и печатаются как есть только `$f` и `$accel`.

Единицы: `$pen_dn`/`$pen_up` - мс, `$bl` - шаги, `$f*`/`$home_*` - шаг/с, `$accel` - шаг/с².

`$$` печатает то, что действует **сейчас**: `$f` - текущая модальная подача, `$accel` - текущее ускорение (стартовое берётся из EEPROM, дальше меняется `M201` и обратно не пишется). `$fdef` - подача из EEPROM, с которой МК стартовал. После `F1200` будет `$f=1200` и `$fdef=800` - это не рассинхрон, это разные вещи.

## 9. Errors

```
error:0x<код> <ТЭГ>
```

Код - hex из той же сквозной шкалы, полоса `0xF0-0xFF`. Тэг - стабильный, для машины. Текст для человека не шлём: его место в логе хоста.

| Код    | Тэг           | Что                                                                                                                                               |
| ---    | ---           | ---                                                                                                                                               |
| `0xF0` | INTERNAL      | внутрянка, баг прошивки                                                                                                                           |
| `0xF1` | BAD_PARAM     | не число / не влезло в int32 / нет значения                                                                                                       |
| `0xF2` | UNKNOWN_CMD   | неизвестная команда или лишний токен                                                                                                              |
| `0xF3` | SOFT_LIMIT    | за пределами `0..travel`                                                                                                                          |
| `0xF4` | BUSY          | команда не разрешена, пока выполняется другая                                                                                                     |
| `0xF5` | STATE         | запрещено в текущем состоянии                                                                                                                     |
| `0xF6` | LINE_TOO_LONG | строка > 64 Б                                                                                                                                     |
| `0xF7` | LINE_TIMEOUT  | строка не закрылась за 200 мс                                                                                                                     |
| `0xF8` | HOMING_FAILED | хоуминг не доехал                                                                                                                                 |
| `0xF9` | ABORTED       | команда прервана `M112`/`!`/`0x18`                                                                                                                |
| `0xFA` | LIMIT_HIT     | концевик во время движения                                                                                                                        |
| `0xFB` | NO_HOME       | нужен `G28`                                                                                                                                       |
| `0xFC` | TOOL_FAULT    | отказ пера. Зарезервирован: датчика касания в железе нет, ловить нечем                                                                            |
| `0xFD` | EEPROM        | обращение к EEPROM провалилось. Зарезервирован: конфиг читается один раз на старте, до баннера, и его провал даёт `0x66 EVCFGER` / `0x67 EVEESUM` |
| `0xFE` | RANGE         | значение вне допустимого диапазона                                                                                                                |
| `0xFF` | UNSUPPORTED   | команда распознана, но выключена в сборке. Сейчас зарезервирован: таких команд в разделах 6-7 нет                                                 |

Правила:

- **Ошибка относится только к этой команде.** Очереди нет, отменять нечего.
- `error:0xF3 SOFT_LIMIT` - команда **отклоняется до начала движения**. Не «доехал до границы и встал»: остановка посреди линии = потерянная геометрия.
- После ошибки связь жива, состояние не меняется, кроме случаев, где явно указан переход (`EVLIMNH` -> `SALA` и т.д.).

## 10. Команда × состояние

`✓` - разрешено, `–` - `error:0xF5 STATE`, но **в `SBUS` вместо него `error:0xF4 BUSY`**, `=` - `error:0xFB NO_HOME` при `home=0`.

| Команда          | SREA | SBUS | SIDL | SPAU | SALA | SEST | SFAU/SFLT/SPWR | `home=0` |
| ---              | ---  | ---  | ---  | ---  | ---  | ---  | ---            | ---      |
| `?`              | ✓    | ✓    | ✓    | ✓    | ✓    | ✓    | ✓              | ✓        |
| `M114`           | ✓    | –    | ✓    | ✓    | ✓    | ✓    | ✓              | ✓        |
| `M112`           | ✓    | ✓    | ✓    | ✓    | ✓    | ✓    | ✓              | ✓        |
| `!`              | ✓    | ✓    | ✓    | ✓    | ✓    | ✓    | –              | ✓        |
| `0x18`           | ✓    | ✓    | ✓    | ✓    | ✓    | ✓    | –              | ✓        |
| `M115` `$$`      | ✓    | –    | ✓    | ✓    | ✓    | ✓    | –              | ✓        |
| `M999`           | –    | –    | –    | –    | ✓    | ✓    | –              | ✓        |
| `G28`            | ✓    | –    | ✓    | ✓    | –    | –    | –              | ✓        |
| `G0` `G1`        | ✓    | –    | ✓    | ✓    | –    | –    | –              | =        |
| `G4`             | ✓    | –    | ✓    | ✓    | –    | –    | –              | ✓        |
| `M3` `M5`        | ✓    | –    | ✓    | ✓    | –    | –    | –              | ✓        |
| `M17` `M18`      | ✓    | –    | ✓    | ✓    | –    | –    | –              | ✓        |
| `G92`            | ✓    | –    | ✓    | ✓    | –    | –    | –              | =        |
| `F` `M201`       | ✓    | –    | ✓    | ✓    | –    | –    | –              | ✓        |

`!` в `SIDL` и `SEST` принимается, но ничего не делает: моторы обесточены, держать нечем (см. 5.7).

### Прочие состояния

| Команда     | SBOO | SMNT | SSLP |
| ---         | ---  | ---  | ---  |
| `?`         | –    | ✓    | ✓    |
| `M112`      | –    | ✓    | ✓    |
| `M999`      | –    | ✓    | –    |
| `$$` `M115` | –    | ✓    | –    |
| `M114`      | –    | –    | –    |
| `!` `0x18`  | –    | –    | –    |
| остальное   | –    | –    | –    |

`SBOO` команд не принимает вообще - порт читается только после баннера. `SMNT` и `SSLP` включаются только кнопкой/меню: команды в них принимаются, но выйти командой нельзя. Так, `M999` в `SMNT` отвечает `ok` и состояние не меняет.

Почему так:

- `G28` разрешён при `home=0` - иначе машина не выйдет из этого состояния **никогда**.
- `M3`/`M5` разрешены при `home=0`: перо не двигает XY, крашнуться нечем, а для диагностики нужно.
- `M112` принимается везде, где МК ещё жив. В `SFAU`/`SFLT`/`SPWR` он **не меняет состояние** и просто отвечает `ok`: моторы уже обесточены, это повторная страховка, а не выход. `!` и `0x18` там запрещены: паузить и ресетить защёлкнувшуюся аварию нельзя, выход только снятием питания. Отсюда и асимметрия между `M112` и `!`.
- `M114` разрешён везде, где жив МК: он ничего не двигает и ничего не меняет, только читает последние известные координаты. В `SBUS` запрещён по другой причине - его `ok` спутается с ответом идущей команды.
- `M17`/`M18` в `SALA`/`SEST` запрещены намеренно: иначе аварию можно было бы обойти сменой питания моторов, минуя `M999`. Выход из этих состояний один - `M999`.
- `M999` из `SEST`, если кнопка ещё нажата, даёт `error:0xF5 STATE`. Отдельного флага «причина SEST» в `<STATE>` нет: хост просто повторяет `M999` раз в 200 мс, пока не получит `ok`.
- В `SFAU`/`SFLT`/`SPWR` принимаются только `?` и `M112`. Остальное - `error:0xF5 STATE`, чтобы хост не висел.

## 11. Приёмка (golden transcript)

Один прогон, по которому пишутся обе стороны. `->` хост, `<-` МК.

```
открыть порт, ждать 2000 мс
<- PLOTTER 2.0.F proto=2 spm=80,80 travel=24000,16000 home=0 reset=POR crash=0
-> ?
<- <STATE S=0xC1 L=0xCE M=0xD0 T=0xE0 x=0 y=0 home=0>
-> G0 X100 Y100
<- error:0xFB NO_HOME
-> G28
<- !EVENT 1 0x11 EVHOMST
<- !EVENT 2 0x03 EVLMSET axis=X
<- !EVENT 3 0x04 EVLMCLR axis=X
<- !EVENT 4 0x03 EVLMSET axis=Y
<- !EVENT 5 0x04 EVLMCLR axis=Y
<- !EVENT 6 0x12 EVHOMEN ms=4120
<- <STATE S=0xC1 L=0xCE M=0xD0 T=0xE0 x=0 y=0 home=1>
<- ok
-> G0 X2400 Y1600
<- !EVENT 7 0x05 EVMSTRT x=0 y=0
<- !EVENT 8 0x06 EVMEND x=2400 y=1600
<- <STATE S=0xC1 L=0xCE M=0xD0 T=0xE0 x=2400 y=1600 home=1>
<- ok
-> M3
<- !EVENT 9 0x0B EVTLDN
<- <STATE S=0xC1 L=0xCE M=0xD0 T=0xE1 x=2400 y=1600 home=1>
<- ok
-> G1 X4800 Y1600 F1200
<- !EVENT 10 0x05 EVMSTRT x=2400 y=1600
<- !EVENT 11 0x06 EVMEND x=4800 y=1600
<- <STATE S=0xC1 L=0xCE M=0xD0 T=0xE1 x=4800 y=1600 home=1>
<- ok
-> M5
<- !EVENT 12 0x0C EVTLUP
<- <STATE S=0xC1 L=0xCE M=0xD0 T=0xE0 x=4800 y=1600 home=1>
<- ok
-> ?
<- <STATE S=0xC1 L=0xCE M=0xD0 T=0xE0 x=4800 y=1600 home=1>
-> M114
<- X4800 Y1600 F1200 PEN=0 HOME=1
<- ok
-> G1 X30000 Y1600
<- error:0xF3 SOFT_LIMIT
-> M112
<- !EVENT 13 0x90 EVESTOP
<- <STATE S=0xC8 L=0xCE M=0xD0 T=0xE0 x=4800 y=1600 home=0>
<- ok
```

Тест-кейсы, которые обязаны проходить:

1. Строка 65 байт -> `error:0xF6 LINE_TOO_LONG`, линк жив.
2. `G1 X1.5 Y0` -> `error:0xF1 BAD_PARAM`.
3. `g1 x100 y100` -> работает (регистр не важен).
4. `G1 X-1 Y0` -> `error:0xF3 SOFT_LIMIT`, моторы не дёрнулись.
5. `G28` до `G0` при `home=0` -> ок, после - `G0` работает.
6. `M112` во время длинного `G1` -> стоп за < 50 мс, `error:0xF9` по текущей команде.
7. Пропал `\n` -> через 200 мс `error:0xF7`.
8. `M999` из `SEST` -> `SREA`, `home=0`, следующий `G0` -> `error:0xFB`.
9. Замолчать на 9 с при простое -> пуш `<STATE L=0xCF ...>`, затем `!EVENT <seq> 0x3B EVLNKTO ms=9000`; моторы держат. После первого же байта - пуш `<STATE L=0xCE ...>`. Во время движения тишина 9 с не должна ничего ронять.
10. `?` в `SBUS` не сбивает ожидание `ok` у `G1`: `<STATE ...>` не терминальный и ожидание не закрывает.
11. `0x18` во время `G1` -> текущей команде `error:0xF9 ABORTED`, затем баннер; `seq` снова с 1, `EVABRT` не шлётся.
12. `M112` во время `G1` -> строго в порядке: `!EVENT <seq> 0x90 EVESTOP`, `error:0xF9 ABORTED` (это `G1`), `<STATE S=0xC8 ...>`, `ok` (это `M112`).
